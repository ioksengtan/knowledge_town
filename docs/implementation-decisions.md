規格書第 9 節列出多項尚未定案的數值與規則。為了讓第一版可以跑起來，這次實作做了以下暫定選擇。都集中在 `src/game/logic.ts`，之後要調整數值只需要改那個檔案，不影響其他程式碼。

## 規格書沒明講、但實作時需要決定的細節

- **每張地圖的資源池是單一數值**（規格書講「資源」用單數，沒有分多種資源類型），程式碼用 `map.resources: number` 表示，升級總部／建築／擴地都花同一種資源。
- **新建領域的分類指派**沿用規格書「依名稱雜湊」的說法，實作為對名稱字串做簡單雜湊後 `mod 4` 對應四個分類（`categoryHash()`）。
- **總部本身在城鎮畫面上顯示成一棟建築**，視覺上借用了「英雄類」的佔位色板（純美術佔位選擇，不代表總部真的屬於英雄類——總部在規格書裡是獨立於四大分類之外的存在，正式美術會依 `docs/art-spec.md` 第 5 節獨立設計）。

## 種子資料

規格書第 8 節提到「5 個領域、21 張卡（20 quiz + 1 reading）」但實際內容在「前版規格」中，這次上傳的文件沒有附上。目前的種子資料（`src/game/seed.ts`）是重新撰寫的 5 個科技領域內容：AI 與機器學習、晶片與硬體、軟體工程、新創產業、科技人物觀察，共 20 張 quiz + 1 張 reading，符合規格書給的數量，但題目內容是新寫的，不是舊版原文。如果你手上有前版規格的原始卡片內容，可以告訴我，我再替換掉種子資料。

新增的第 6 個領域「抽象化思維」（`domain_abstraction_thinking`）沿用同一套規則：
- **分類交由 `categoryHash()` 決定，不採用來源資料裡寫的 `category: "training"`**——這是規格書「系統依名稱雜湊自動指派分類」的既有規則，為了跟其他領域一致，沒有開放手動指定分類。`categoryHash('抽象化思維')` 算出來是 `hero`（英雄類），跟來源資料寫的「training」不同。如果你想要它落在訓練類，目前唯一的調整方式是改領域名稱（雜湊值會跟著變），或之後真的要支援手動選分類的話再另外討論。
- 來源資料的 quiz 卡只有單一「answer」，沒有選項——但這款產品的問答卡是選擇題，所以每題都補了 3 個干擾選項，正確答案保留原文字。
- 閱讀卡的每一頁原本是「content + example（比喻）」的結構，這次直接把資料模型從 `pages: string[]` 改成 `pages: { content: string; example?: string }[]`，讓「例如」比喻可以用獨立的樣式呈現（金色左邊框的引用框），而不是把兩段文字硬併成一段。舊的閱讀卡（大型語言模型的訓練三階段）也一併轉成新格式（只是沒有 example）。

## 存檔版本與內容更新

目前每次改動種子內容（新增領域、改資料結構）都會把 zustand persist 的 storage key 往上 bump 一版（目前是 `knowledge-town-save-v3`），這會讓瀏覽器裡舊的本機存檔直接失效、重新從種子資料開始。這在還沒有正式使用者、只有本機測試的階段沒問題，但正式上線、玩家開始累積真實進度之後就不能再這樣做了——屆時需要寫一個「合併」邏輯（保留玩家既有進度，只把種子資料裡缺少的新領域/卡片補進去），而不是整包 bump 版本重置。
