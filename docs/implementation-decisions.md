# 實作決策紀錄 — 補完規格書「待定案」項目

規格書第 9 節列出多項尚未定案的數值與規則。為了讓第一版可以跑起來，這次實作做了以下暫定選擇。都集中在 `src/game/logic.ts`，之後要調整數值只需要改那個檔案，不影響其他程式碼。這份文件持續累積到 v7.6，新決策直接加在表格最後並標註版本。

| **（v7.6 新增）** 課程內課堂是否強制依序解鎖 | 不強制，玩家可以自由挑選任一堂先做，只有「全部完成」這個條件會觸發課程獎勵 | `courseLessonsDone()`（`store.ts`） |
| **（v7.6 新增）** 同一棟研究中心可以同時進行幾個課程 | 不限制數量，`Course.domainId` 只是單純指向研究中心，一棟研究中心底下可以掛任意多個課程 | `types.ts` 的 `Course`、`coursesForDomain()` |
| **（v7.6 新增）** 每日任務 | **本次未實作**——規格書 5.10 列出的待定案項目（帳號層級 vs 每張地圖、任務內容、獎勵種類與數量、連續完成獎勵、可否補做）幾乎全部空白，貿然生出一整套規則風險較高，先擱置，等規格更具體再做 | — |

| **（後續補做）** 世界地圖／城鎮畫面的等距呈現方式 | 一開始只用 CSS grid 排卡片、CSS 畫個菱形當裝飾，**不是真正的等距投影**。使用者指出後補上真正的等距座標系統：`isoToScreen()` 把 (col,row) 格子座標換算成螢幕 x/y（2:1 菱形比例），世界地圖用簡單的棋盤排列（`gridPosition()`，對應規格書「系統化排法」），城鎮內部用一個從總部往外展開的環狀排列（`ringPosition()`，單純決定畫面上的座標，不影響「哪個 slotIndex 蓋在哪」這個既有規則——那個規則仍然是依序自動排下一個空位，兩者是不同層次的決定）。深度排序（誰疊在誰前面）用簡化算法：`zIndex = row 相關的值`，不是嚴謹的畫家演算法，多棟建築密集重疊時可能還是會有排序不夠精細的情況 | `src/game/iso.ts`、`Town.tsx`、`WorldMap.tsx` |

## 規格書沒明講、但實作時需要決定的細節

- **每張地圖的資源池從單一數值改成三種資源**（`{ wood, ore, food }`），跟著 v7.4/v7.5 規格走；升級總部／建築／擴地現在都要同時檢查三種資源夠不夠（見上表「三種資源怎麼花」）。
- **新建領域的分類指派**沿用規格書「依名稱雜湊」的說法，實作為對名稱字串做簡單雜湊後取分類數量的模數（`categoryHash()`）。**v7.6 更新**：英雄類移除後分類只剩 3 種，雜湊改成 `mod 3`——這代表同一個領域名稱在 v7.2 版（mod 4）跟現在（mod 3）算出來的分類可能不一樣，是雜湊函式本身的正常結果，不是 bug。
- **總部不再借用任何分類的佔位色板**——v7.2 版時借用「英雄類」純粹是因為當時英雄類存在且視覺上最搭「殿堂感」；英雄類移除後，總部改成完全獨立的第 4 套佔位色板（`TOWNHALL_BODY` in `palette.ts`），不屬於三大分類中任何一種，這本來就符合規格書「總部造型獨立設計」的說法，只是 v7.2 版偷懶借用了英雄類的顏色。
- **QuizCard 的 `explanation` 欄位改名為 `example`**，對應規格書 v7.3 新增的「卡片固定搭配一個具體例子」設計——功能沒變（答對/答錯後顯示在結果區的輔助說明文字），只是改名跟 `ReadingPage.example` 用同一個詞，避免同一個概念在資料模型裡有兩個名字。
- **`Domain.resourceType`（規格書列為欄位）沒有真的存成欄位**，改成用 `CATEGORY_RESOURCE[category]` 即時算——因為這個值 100% 由 `category` 決定，存成獨立欄位只會多一個「跟 category 對不上」的風險，算是比規格書資料模型更保守的實作方式，行為完全等價。
- **課程完成的獎勵是「一次性加進地圖的鐵礦池」**，不是加進某個獨立的「課程獎勵」欄位——因為規格書寫明課程獎勵固定是鐵礦，跟一般研發類建築產出的資源種類相同，沒有理由另外開一個資源軌道。
- **（後續補做）新增 `Domain.buildingName` 欄位，跟 `Domain.name`（知識主題）分開**：規格書原本的資料模型只有 `name`，同一個欄位既是知識主題、也是城鎮畫面上的建築標籤。使用者實際玩過後回饋「AI 與機器學習」「軟體工程」這種標題看起來不像城鎮裡的建築，應該要有一個「建築在城鎮裡叫什麼名字」的獨立欄位，才有代入感（比照真正 Last War 的「兵工廠」「軍營」這種建築名，而不是直接顯示裡面裝的內容）。改法：
  - 每個分類有一組風味名稱池（`BUILDING_NAME_POOL` in `logic.ts`，例如生產類：糧倉／煉製廠／物資集散地...），刻意跟 `art-spec.md` 的 5 階段造型名稱不重複，避免兩個標籤看起來像同一個東西
  - 新建領域時（`addDomain`）自動從對應分類的名稱池裡，挑一個「這張地圖裡同分類建築還沒用過」的名字（`generateBuildingName()`），池用完就退化成「糧倉 2」這種編號後綴
  - 種子資料的 6 個領域則是手動指定固定的建築名稱（而不是跑自動生成），方便挑選跟內容調性搭配的名字
  - 兩個名字都會顯示，但用途分開：城鎮畫面（`Town.tsx` 的 iso tile）建築名稱是主標籤（粗體）、知識主題是副標籤；建築詳情頁反過來，知識主題是 H1（因為進到這頁就是要處理這個主題的卡片），建築名稱變成上面一小行風味標籤
  - 這個欄位一旦在建立時決定就不會再變，即使之後名稱池內容調整，既有建築的名字也不會被追溯修改（跟 `category` 的既有行為一致）

## 種子資料

規格書第 8 節提到「5 個領域、21 張卡（20 quiz + 1 reading）」但實際內容在「前版規格」中，這次上傳的文件沒有附上。目前的種子資料（`src/game/seed.ts`）是重新撰寫的 5 個科技領域內容：AI 與機器學習、晶片與硬體、軟體工程、新創產業、科技人物觀察，共 20 張 quiz + 1 張 reading，符合規格書給的數量，但題目內容是新寫的，不是舊版原文。如果你手上有前版規格的原始卡片內容，可以告訴我，我再替換掉種子資料。

新增的第 6 個領域「抽象化思維」（`domain_abstraction_thinking`）沿用同一套規則：
- **分類交由 `categoryHash()` 決定，不採用來源資料裡寫的 `category: "training"`**——這是規格書「系統依名稱雜湊自動指派分類」的既有規則，為了跟其他領域一致，沒有開放手動指定分類。`categoryHash('抽象化思維')` 目前（v7.6，3 分類）算出來是 `production`（生產類）；v7.2 版（4 分類）當時算出來是 `hero`。分類會隨分類總數變動而改變是雜湊函式的正常行為。如果想要它落在訓練類，目前唯一的調整方式是改領域名稱。
- 來源資料的 quiz 卡只有單一「answer」，沒有選項——但這款產品的問答卡是選擇題，所以每題都補了 3 個干擾選項，正確答案保留原文字。
- 閱讀卡的每一頁原本是「content + example（比喻）」的結構，這次直接把資料模型從 `pages: string[]` 改成 `pages: { content: string; example?: string }[]`，讓「例如」比喻可以用獨立的樣式呈現（金色左邊框的引用框），而不是把兩段文字硬併成一段。舊的閱讀卡（大型語言模型的訓練三階段）也一併轉成新格式（只是沒有 example）。

## 存檔版本與內容更新

目前每次改動種子內容或資料結構都會把 zustand persist 的 storage key 往上 bump 一版（目前是 `knowledge-town-save-v5`——最新一次是新增 `Domain.buildingName` 必填欄位，舊存檔裡的 Domain 物件沒有這個欄位，形狀對不上，照慣例 bump 版本），這會讓瀏覽器裡舊的本機存檔直接失效、重新從種子資料開始。這在還沒有正式使用者、只有本機測試的階段沒問題，但正式上線、玩家開始累積真實進度之後就不能再這樣做了——屆時需要寫一個「合併」邏輯（保留玩家既有進度，只把種子資料裡缺少的新領域/卡片補進去），而不是整包 bump 版本重置。

## v7.6 新機制的實作範圍說明

- **拿掉英雄類**：`BuildingCategory` 從 4 個值改成 3 個，`categoryHash()` 的 mod 數跟著變，`palette.ts` 拿掉英雄類色板，`art-spec.md`／`art-outsourcing-brief.md` 的造型數量都同步從 20/25 張改成 15/20 張。

- **研究中心／課程機制**：資料模型（`Domain.isResearchCenter`、`Course`、`Card.courseId`）與 store 邏輯（課堂完成不逐卡給資源、課程全部完成才一次發鐵礦）都已經實作完成，並用一段暫時性的瀏覽器測試腳本驗證過整個流程（把 `d-people` 設為研究中心、掛一個 2 堂課的測試課程，確認第 1 堂不給資源、第 2 堂觸發課程完成並發放 10 鐵礦）。**但種子資料裡目前沒有任何一棟建築被設為研究中心，也沒有真正的課程內容**——規格書 5.9 明確說 Cozy AI Kitchen 系列只有「磚頭比喻」一個課堂內容經過確認可靠，其餘三個（Embeddings/Tokens/Persona-Agent）只有摘要、沒有逐字稿佐證，為了不憑空腦補內容，這次沒有把任何課程種進 `seed.ts`。等你補齊可靠的來源資料，我再把真正的課程內容加進去。
