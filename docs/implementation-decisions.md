# 實作決策紀錄 — 補完 v7.2 規格書「待定案」項目

規格書第 9 節列出多項尚未定案的數值與規則。為了讓第一版可以跑起來，這次實作做了以下暫定選擇。都集中在 `src/game/logic.ts`，之後要調整數值只需要改那個檔案，不影響其他程式碼。

| 待定案項目 | 這次的選擇 | 位置 |
|---|---|---|
| 15 級升級花費曲線 | `cost(level) = round(5 × (level+1)^1.6)`，數值無上限延伸的公式曲線（不是查表），跟舊版 6 級曲線 `0/5/10/18/30/50` 走勢一致但延展到任意等級 | `upgradeCost()` |
| 總部與一般建築花費曲線是否相同 | 相同，共用同一條曲線 | `upgradeCost()` |
| 地塊初始容量 | 6 格 | `INITIAL_LAND_CAPACITY` |
| 每次擴地增加的地塊數 | +4 格 | `LAND_PER_EXPANSION` |
| 擴地花費曲線 | `cost = round(50 × 1.6^已擴地次數)`，走獨立的費用軌道（如規格書 5.3 所述） | `expansionCost()` |
| 新建築在共用地塊上的擺放規則 | 依序自動排下一個空位（不開放玩家自由選位置） | `store.ts` 的 `addDomain` |
| 總部升級是否受擴地影響 | 否，總部不佔用地塊、升級只消耗資源 | `Town.tsx` |
| 總部是否有獨立解鎖內容 | 目前沒有，維持與一般建築同一套視覺升級曲線 | — |
| 15 級後彩蛋造型觸發條件 | 尚未實作，程式碼只把外觀鎖在階段 5（`appearanceStage()` 對超過 15 級的數值封頂），三個候選方向都還沒選 | `appearanceStage()` |
| quiz 的「目前輪數」定義 | **v2 修正**：改成真實日曆天（`currentRound() = Math.floor(Date.now() / 一天的毫秒數)`），不是答題次數。原本用「每答一次 quiz 就 +1」當作輪數，實測後發現兩個問題：(1) UI 沒有真的擋住未到期的卡片，同一張卡可以無限狂點刷資源；(2) 就算擋住，21 張卡池 + interval 封頂 30 的情況下，輪數本身無法自己往前走，跑一段時間後所有卡都不到期，遊戲會死鎖。改成真實時間後，到期日永遠會自然到來，且已在 UI／store 兩層都強制擋下未到期的作答 | `currentRound()`（`logic.ts`）、`answerQuiz()` 的 `notDue` 擋下（`store.ts`）、`QuizModal.tsx` 按鈕 disable |

## 規格書沒明講、但實作時需要決定的細節

- **每張地圖的資源池是單一數值**（規格書講「資源」用單數，沒有分多種資源類型），程式碼用 `map.resources: number` 表示，升級總部／建築／擴地都花同一種資源。
- **新建領域的分類指派**沿用規格書「依名稱雜湊」的說法，實作為對名稱字串做簡單雜湊後 `mod 4` 對應四個分類（`categoryHash()`）。
- **總部本身在城鎮畫面上顯示成一棟建築**，視覺上借用了「英雄類」的佔位色板（純美術佔位選擇，不代表總部真的屬於英雄類——總部在規格書裡是獨立於四大分類之外的存在，正式美術會依 `docs/art-spec.md` 第 5 節獨立設計）。
