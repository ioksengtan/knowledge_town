# 科技知識苑 — 產品規格書

版本：v7.6（規格討論階段，尚未落地為程式碼）

---

## 1. 產品定位

一個以「收集 + 建設」為核心迴圈的科技知識吸收平台。設計概念完全比照 SLG 手遊《Last War》的基地養成邏輯——蓋建築、升級、擴張地盤——但**拿掉其他玩家／competitive 對戰的部分，純粹是自我對自我的升級**。驅動這個迴圈的燃料是真實的知識吸收行為（答對問答、讀完摘要），讓養成遊戲的爽感直接對應到使用者真的有累積價值的學習成果。

目前內容聚焦：**科技知識**（AI/機器學習、晶片硬體、軟體工程、新創產業、科技人物觀察等）。

---

## 2. 核心使用者旅程

1. 打開世界地圖 → 看到目前已經開始經營的城鎮地圖（可能不只一張）
2. 選一張地圖點進去 → 看到總部 + 一整塊已經蓋了不少建築的開放平地
3. 點一棟建築 → 看到裡面的知識碎片（卡片）清單，挑一張複習或閱讀
4. 完成後獲得**這張地圖專屬的資源**（不同地圖資源不互通）
5. 用資源做兩件事之一：**升級某棟建築**（含總部），或**擴充城鎮共用的可建地**（讓城鎮能蓋更多建築）
6. 隨時可以新增地圖，不需要先蓋完現有的——多張地圖之間自由切換心力
7. 當一張地圖裡所有建築都到達視覺封頂等級，這張地圖「完工」，呈現固定的主題終貌——這是一個里程碑成就，不是解鎖新地圖的門檻（新地圖隨時可以開）

## 3. 資討架構（三層，隨討論演進而定案）

### 3.1 世界地圖層
- **改為等距像素風地圖**（不再是平面六邊形棋盤），每張城鎮地圖＝世界地圖上一塊獨立的等距小島／地塊
- 排列邏輯沿用先前「棋盤自動擴張」的系統化排法（依地圖數量自動擴張版面），只是視覺呈現換成等距像素風——這一層是「地圖選擇總覽」，不是玩家精心規劃的建造版面，所以用系統化排列不衝突先前否決螺旋演算法的理由（那個否決是針對「城鎮內部建造版面」，這裡是不同的使用情境）
- **每個小島＝一張完整獨立的城鎮地圖**，可以隨時新增，不需要先完成現有地圖
- 不同主題的地圖：目前定案第一套主題是 **Last War 寫實軍事風**；曾討論過的合掌村、賽博龐克等主題暫緩，列在待辦

### 3.2 城鎮內部層（每張地圖的內部結構）
- **總部（Town Hall）**：固定在地圖正中央，是視覺錨點，但**現在可以升級**——用這張地圖自己的資源升級，跟其他建築共用同一套經濟系統，不是另外的貨幣
  - **總部等級是其他所有建築的等級天花板**：任何領域建築的等級不能超過總部目前的等級，想繼續衝某棟建築的等級，得先確保總部等級夠高，不夠就得先花資源升總部
  - 總部的升級曲線與外觀階段數，跟其他建築完全一致：**15 級數值、每 3 級換一次外觀，共 5 個階段**（詳見 5.4）
- **城鎮就是一整塊連續的可建地，不再切分成獨立分區**——總部周圍是一片開放平地，建築物依序蓋上去，類似真正 Last War 裡玩家可以自由把建築拖來拖去擺放的那種開放式基地感，而不是切成四個各自獨立、互不相通的小區塊
- 建築仍然有**三種分類**（⚙️ 生產類／🎯 訓練類／🔬 研發類，**v7.5 拿掉原本的🎖️英雄類**），但分類現在**只影響建築的造型設計**（見 5.5），不再決定建築蓋在地圖上的哪個區域——同一塊地上，不同分類的建築可以混著蓋
- 整塊可建地有**共用的地塊容量**（不分類別），蓋滿了需要「擴地」（見 5.4）才能繼續新增建築
- 新建領域（知識主題）時，系統依名稱雜湊自動指派分類（決定造型），並佔用整塊可建地上下一個空地塊；地塊已滿時會擋下新增動作，提示需要先擴地

### 3.3 建築＝領域
- 每個地塊上的一棟建築，對應一個知識領域（例如「AI 與機器學習」）
- 建築內部裝著該領域的所有知識卡片（問答型／閱讀型）
- 建築有自己的**等級**（見 5.4），由玩家花這張地圖的資源手動升級，但不能超過總部等級天花板（見 5.2）

## 4. 資料模型（草案，尚未寫入程式碼）

### TownMap（新增概念）
| 欄位 | 說明 |
|---|---|
| id | UUID |
| theme | 主題（目前僅「Last War 寫實軍事風」一種已定案） |
| resources | 這張地圖專屬的資源池，**（v7.4 改版，v7.5 改為三資源）改為三種基礎資源分別計數**：`{ wood: N, ore: N, food: N }`，與其他地圖不互通 |
| landCapacity | 整塊城鎮共用的地塊容量與已用數量（不分類別、不分區） |
| townHallLevel | 總部等級（數值不封頂，外觀 15 級封頂），是這張地圖所有建築的等級天花板 |

### Domain（＝一棟建築）
| 欄位 | 說明 |
|---|---|
| id | UUID |
| name | 領域名稱 |
| category | 自動指派的分類（production / training / rnd，**v7.5 拿掉 hero**） |
| mapId | 所屬的 TownMap |
| level | 數值等級，理論上無上限，**但實際可升等級受限於 `townHallLevel`**（不可超過總部目前等級） |
| **resourceType**（v7.4 新增，v7.5 改為三資源） | 依 `category` 自動決定，該建築完成卡片時產出的資源種類：production→food、training→wood、rnd→ore |
| **isResearchCenter**（v7.4 新增） | boolean，僅 `category = rnd` 的建築中最多一棟可設為 true，設為 true 時啟用「課程」機制（見 5.9），且該棟建築底下的卡片不適用一般的逐卡給資源規則 |

### Course（v7.4 新增概念，僅研究中心建築底下存在）
| 欄位 | 說明 |
|---|---|
| id | UUID |
| name | 課程名稱（例如「Cozy AI Kitchen」） |
| domainId | 所屬的研究中心 Domain（`isResearchCenter = true`） |
| lessonIds | 屬於這個課程的課堂（Card）id 清單 |
| completed | 是否所有課堂都已完成，完成時觸發一次性資源獎勵（見 5.9） |

### Card（quiz / reading 兩種，本版新增 example、courseId 欄位；其餘欄位維持既有設計，詳見第 8 節前版規格）
| 欄位 | 說明 |
|---|---|
| id | UUID |
| type | "quiz" 或 "reading" |
| domainId | 所屬的 Domain（建築） |
| example | 具體例子，用來輔助理解該張卡片的知識點。reading 卡可逐頁附上一個例子；quiz 卡可附在答案之後。**選例原則**：優先挑「方向與知識點一致」的生活化類比——例如知識點強調「抽象化＝原理可遷移、不綁死於表層操作」，選例時要避免挑到「往下鑽細節」方向相反的比喻（如「先搞懂底層機械原理」這類例子雖然也在談「懂原理」，但方向是往下而非往上，容易造成誤解）；同一個領域內的多頁 reading 卡，也可以刻意用同一個比喻貫穿全部頁面，幫助記憶與前後呼應 |
| **courseId**（v7.4 新增） | 若此卡屬於研究中心的課堂則有值，否則為 null。有值時，此卡完成**不觸發**一般的逐卡給資源規則（見 5.9），改為等該 Course 底下所有課堂都完成後，一次性發放資源 |
| （其餘 quiz/reading 既有欄位不變） | 見 5.6、5.7 |

## 5. 核心機制

### 5.1 世界地圖與多地圖系統
- 新增地圖是**隨時可做的動作**，不需要先蓋完現有地圖
- 各地圖資源、建築等級、擴地進度**完全獨立、互不流通**——每張地圖都是從零開始的一場新遊戲
- 玩家可以自由決定心力分配：專心衝一張蓋到底，或是多張同時慢慢養、在成本變高時切換去蓋別張
- 「完工」（該地圖所有建築都到達視覺封頂等級）是**里程碑成就，不是解鎖新地圖的門檻**——呈現這張地圖主題的固定終貌，純粹的完成感獎勵

### 5.2 總部升級與等級天花板
- 總部使用該地圖的資源升級，升級曲線與外觀階段數跟其他建築完全一致（15 級數值、每 3 級換一次外觀、共 5 個階段，詳見 5.4）
- **總部目前等級＝這張地圖所有領域建築的等級上限**：任何一棟建築想升到超過總部目前等級，升級按鈕會被擋下，需要先把總部升級上去
- 這個機制製造真正 SLG 的節奏感：蓋著蓋著撞到總部天花板 → 逼玩家回頭投資總部 → 總部升完，底下所有建築的天花板一起往上推一階
- **待定案**：總部本身的升級要不要也受擴地影響、或是否有獨立的特殊解鎖內容（例如總部到達某階段解鎖新分類）——目前尚未討論

### 5.3 擴地機制
- 擴地是**獨立於建築升級的另一個動作**，花這張地圖的資源，把整塊城鎮的共用地塊容量 +N
- 城鎮的可建地有初始容量上限，蓋滿後需要擴地才能繼續新增建築（不分類別，四種建築共用同一個地塊池）
- 擴地花費隨階段遞增（概念上跟建築升級費用曲線類似，但走獨立的費用軌道）
- **待定案**：地塊初始容量的實際數字、每次擴地增加的地塊數、擴地花費曲線的具體數值、新建築在共用地塊上的實際擺放順序／規則（例如是否可以自由選位置，還是依序自動排下一個空位）

### 5.4 領域建築升級：15 級數值、5 個外觀階段
- 建築等級**數值上不封頂**，可以持續往上升，讓玩家不會遇到「練到頂沒事做」的空窗期
- 但**外觀資產只做 5 個階段**，每 3 級切換一次（Lv1–3／4–6／7–9／10–12／13–15），15 級之後外觀永久定格在第 5 階段（封頂造型），即使數值繼續往上漲，外觀也不會再變
- **實際可升到多高，受總部等級天花板限制**（見 5.2）
- 這個設計對應真正 SLG 遊戲的常見做法：升級數字持續有感，但美術資產只需要做幾個里程碑造型，不用每級都重畫
- **預留彩蛋鉤子**：未來可能在 15 級之後解鎖隱藏的第 6 階段造型，觸發條件尚未定案，列了三個方向待選：
  1. 數值門檻型（例如單棟建築衝到 30 級、50 級解鎖）
  2. 全部建築達成型（整張地圖所有建築都超過 15 級才解鎖彩蛋造型，屬於地圖等級的集體成就）
  3. 隱藏條件型（不公開觸發條件，靠玩家意外發現）
- **待定案**：15 級的實際升級花費曲線（目前只有舊版 6 級曲線 0/5/10/18/30/50，尚未展開成 15 級版本）；總部與一般建築的花費曲線是否相同也待定案

### 5.5 三大分類的獨立造型設計（Last War 寫實軍事風，第一套主題已定案；v7.5 拿掉原本的🎖️英雄類）

顏色漸層邏輯**四類統一**：每個階段的主色調都朝同一種「越亮＝等級越高」的方向走（沿用先前「顏色朝金色收斂」的概念延伸為「材質從簡陋朽舊到堅固精緻」），差異只在造型元件本身，讓玩家一眼認得出類別，同時一眼認得出等級高低。

| 階段 | 造型描述 |
|---|---|
| 1 | 簡易木造倉庫，單一儲糧棚 |
| 2 | 圍起鐵絲網的儲料場，加了兩座儲存槽 |

| 4 | 煉製廠區，多根管線＋儲油槽 |
| 5（封頂） | 完整生產園區，多座儲槽＋煙囪，規模最大 |

**🎯 訓練類（工程師培訓意象）**

| 階段 | 名稱 | 造型描述 |
|---|---|---|

### 5.6 問答型卡片（quiz）：間隔複習
（沿用既有設計，未變動）
- 答對：`streak += 1`，`interval = min(interval × 2, 30)`，`stage = min(3, floor(streak / 2))`，`due = 目前輪數 + interval`，`claimed = true`
- 答錯：`streak = max(0, streak - 1)`，`interval = 1`，`stage = max(0, stage - 1)`，`due = 目前輪數 + 1`（claimed 不會被收回）
- 四階段視覺：🌱 幼苗 → 🌿 幼株 → 🌳 成木 → ✨ 覺醒

### 5.7 閱讀型卡片（reading）：翻頁完成
（沿用既有設計，未變動）
- 多頁內容，翻到最後一頁按「完成閱讀」即開墾，不進複習佇列（`due = Infinity`）

### 5.8 資源與連擊
- 答對 quiz：`gain = 1 + floor(combo / 3)`；讀完 reading（首次）：`gain = pages.length`
- 答錯 combo 歸零
- **資源現在是「每張地圖各自獨立」的資源池**，不是全域共用（這是本版最大的機制變動之一）——地圖 A 賺到的資源只能花在地圖 A 的升級／擴地上
- **（v7.4 改版，v7.5 改為三種）資源改為三種基礎資源**：木材／鐵礦／糧食（拿掉原本的金幣，因為金幣原本對應的🎖️英雄類已移除），取代原本單一資源池；`gain` 的計算方式不變，差別是**依完成卡片所屬建築的 `resourceType` 決定發放哪一種資源**（見 4 節 Domain.resourceType 對應表：production→food、training→wood、rnd→ore）
- **例外**：`courseId` 不為 null 的卡片（即研究中心的課堂）不適用本節的逐卡發放規則，改用 5.9 的課程完成機制

### 5.9 研究中心與課程機制（v7.4 新增）
- 🔬研發類底下最多可指定一棟建築為「研究中心」（`isResearchCenter = true`）
- 研究中心內部的知識內容，先分組成「課程」（Course），課程底下才是個別「課堂」（Lesson，資料結構上就是既有的 Card）
- **課堂本身完成（答對 quiz／讀完 reading）不直接發放資源**，只會正常記錄卡片自身的狀態（streak、interval、claimed 等，見 5.6、5.7）
- **當一個課程底下所有課堂都完成後，才一次性發放資源獎勵**，資源種類固定為**鐵礦**（因為研究中心屬於🔬研發類）
- **待定案**：課程完成時發放的鐵礦數量曲線（是否隨課程內課堂數量而定、是否有額外倍率）；課程內課堂的完成順序是否強制照順序解鎖，還是可以自由挑選；同一棟研究中心底下可以有幾個課程同時進行中，尚未討論
- 目前規劃第一個課程：改編自《Cozy AI Kitchen》系列（Microsoft Developer YouTube 頻道）的 AI 核心概念比喻——目前僅確認①「磚頭比喻＝模型知識靜態性」這個課堂內容可靠，②③④（Embeddings/Tokens/Persona-Agent 比喻）因原始資料只有摘要、缺乏逐字稿佐證，暫緩製作，待補充更完整的來源資料後再展開

### 5.10 每日任務（v7.5 新增）
- 每日任務是**額外的資源獎勵管道**，疊加在既有的「答對/讀完卡片給資源」機制之上，不取代它——資源獲取維持**主動學習驅動**，不引入放置型／被動掛機產出（不做 Last War 那種「建築隨時間自動生成資源」的 AFK 機制，這是刻意的產品定位選擇，見商業評估紀錄）
- 任務範圍是玩家帳號層級，還是「每張地圖各自有自己的每日任務」，**待定案**（傾向account層級，因為「每天登入做點事」的習慣養成，通常不需要拆分到每張地圖）
- 任務內容草案（暫定，待定案）：例如「今天完成 N 張卡片」「今天至少完成 1 張 reading 卡」「今天升級任一建築 1 次」
- 完成任務的獎勵：**待定案**——是給固定數量的三種基礎資源其中一種／隨機一種，還是有獨立於 wood/ore/food 之外的每日任務專屬獎勵，尚未討論
- **待定案**：每日任務是否有連續完成天數的額外獎勵（類似 streak 機制）；任務數量（每天幾個任務）；任務是否可以補做（例如昨天沒做，今天還能不能追溯完成）

### 5.11 村民（v7.6 新增，純裝飾性，不影響任何數值機制）
- 村民是**環境動畫層級的視覺元素**，在城鎮的可建地上隨機走動、偶爾停在建築物旁邊——沒有互動性，玩家不能操作、指派、或點擊村民做任何事
- **不進入資料模型**：不新增欄位到 TownMap 或 Domain，屬於前端渲染邏輯，依現有的 `townHallLevel` 或建築等級總和去決定畫面上要渲染幾個村民、村民的動作變化，後端資料完全不需要異動
- **觸發邏輯**：村民數量／熱鬧程度跟著總部等級或城鎮整體發展度（例如所有建築等級總和）連動——城鎮越發達，畫面上走動的村民越多，賦予「這座城鎮活起來了」的視覺回饋
- **可選加分項（非必須）**：呼應 5.4／5.5 的「五階段外觀」設計語言與「材質從簡陋到精緻」的整體美術邏輯，城鎮發展初期村民造型簡陋、發展到後期造型可以隨之「升級」，但這屬於美術資產的加分項，不影響核心機制設計

## 9. 目前限制／待定案事項

- **多地圖系統、擴地機制、總部天花板機制、15 級 5 階段建築、四大類獨立造型——目前全部停留在規格討論階段，尚未寫入程式碼**（依使用者要求「先討論規格，不急實作」）
- 15 級的實際升級花費曲線尚未定案；總部與一般建築的花費曲線是否相同也待定案
- 擴地花費曲線、地塊初始容量、每次擴地增加的地塊數，尚未定案
- 新建築在共用可建地上的實際擺放規則（自由選位置 vs 依序自動排下一個空位）尚未定案
- 總部升級是否也受擴地影響、總部是否有獨立的特殊解鎖內容，尚未討論
- 彩蛋造型（15 級後的隱藏第 6 階段）觸發條件尚未定案，僅列出三個候選方向
- 世界地圖的等距像素呈現方式（每張地圖用什麼視覺代表——完工程度／主題差異怎麼表現）尚未細化
- 其他地圖主題（合掌村、賽博龐克等）暫緩，僅 Last War 寫實軍事風完成規格定稿
- 舊版「無使用者新增卡片」「置頂/搬到中央」等既有限制與機制，在新架構下需要重新對應（例如「置頂」在新架構下應該對應什麼行為，尚未重新定義）
- **（v7.4 新增）** 課程完成時發放的鐵礦數量曲線尚未定案；課程內課堂是否強制依序解鎖尚未定案；同一棟研究中心可同時進行幾個課程尚未討論
- **（v7.4 新增）** Cozy AI Kitchen 課程目前只有「磚頭比喻」一個課堂內容確認可靠，其餘（Embeddings/Tokens/Persona-Agent）待補充更完整來源資料後才能製作，避免內容是憑摘要腦補出來的
- **（v7.5 新增）** 每日任務的任務範圍（帳號層級 vs 每張地圖各自）、任務內容、獎勵種類與數量、連續完成獎勵、可否補做——皆尚未定案，僅有草案方向
- **（v7.6 新增）** 村民的具體渲染邏輯（數量與等級的對應公式、動作種類、是否隨階段換造型）尚未細化，屬於前端實作階段才需要決定的細節

## 10. 設計演進紀錄（決策脈絡）

1. **v1**：單一領域，卡片＝六邊形地塊，答對開墾地塊，地塊數解鎖建築
2. **v2**：六邊形地塊改為完整大六邊形棋盤（自動擴張），解決視覺不像大六邊形的問題
3. **v3**：導入「六邊形由三角形構成，可再細分」的碎形概念，支援不限層數、鏡頭縮放導覽
4. **v4**：確立兩層架構——世界地圖（多六邊形）＋領域內部（三角形碎形）
5. **v4.1–v4.3**：加入閱讀型卡片；關閉使用者手動新增卡片；內容特化為科技五大領域
6. **v5.0–v5.1**：三角形碎形簡化為固定 6 城鎮；城鎮等級改為玩家手動花資源升級；修正升級視覺回饋不足的問題（顏色朝金色收斂、圖示放大、軍階點）
7. **v6**：整套視覺改為等距像素風城鎮，領域直接對應建築，拿掉固定 6 格限制，世界地圖一度被拿掉、城鎮中心成為唯一主畫面
8. **v7**：
   - 放棄程序化的螺旋演算法排位，改用真正 SLG 的設計思路：固定分區佈局＋獨立擴地動作
   - 重新引入世界地圖，但意義從「知識分類」改為「一張張完全獨立、資源不互通的城鎮地圖」，可隨時新增，不設解鎖門檻
   - 討論並暫緩多套主題風格（合掌村、賽博龐克），改為先定案 **Last War 寫實軍事風**作為第一套主題
   - 建築升級曲線從 6 級 6 造型，改為 **15 級數值、5 個外觀階段**（每 3 級換一次），15 級外觀封頂但數值不封頂，預留未來彩蛋造型的鉤子
   - 四大分類（生產／訓練／英雄／研發）從共用一套模板，改為**各自獨立設計造型**；訓練類的軍事兵營意象改為工程師培訓意象
9. **v7.1**：
   - 世界地圖層改為**等距像素風地圖**（拿掉平面六邊形棋盤），每張城鎮地圖＝世界地圖上一塊獨立的等距小島，排列邏輯仍沿用系統化的自動擴張（因為這一層是地圖總覽而非精心規劃的建造版面，跟先前否決螺旋演算法的情境不同）
   - **總部改為可升級**，且**總部等級＝該地圖所有建築的等級天花板**，升級曲線與其他建築一致（15 級、5 階段），落地真正 Last War 的核心節奏機制（先前只有其他四類建築可升級，總部純裝飾）
10. **v7.2**：
   - **拿掉四個固定分區的空間劃分**——城鎮改回一整塊連續的開放可建地，不再切成生產／訓練／英雄／研發各自獨立的小區塊，更貼近真正 Last War 玩家可自由擺放建築的開放式基地感
   - 建築分類（⚙️生產／🎯訓練／🎖️英雄／🔬研發）保留，但**分類現在只決定造型設計，不再決定蓋在地圖上的哪個區域**——擴地也從「各分區獨立擴地」改為「整塊城鎮共用一個地塊池」
   - 本版仍停留在規格文件階段，尚未寫入程式碼
11. **v7.3（目前版本）**：
   - **Card 模型新增 `example` 欄位**：每張卡片除了知識點本身，固定搭配一個具體例子輔助理解
   - 起因：實測製作一則知識內容（「Abstraction Is All You Need」相關卡片，歸類進訓練類領域）時，發現例子如果選錯比喻方向（例如把「抽象化＝往上一層、原理可遷移」誤類比成「往下鑽底層機械細節」），反而會讓學習者誤解核心概念——因此把「例子」正式收進資料結構，並訂出選例原則（方向要與知識點一致），而非只是內容文字裡順手加的一段話
   - 附帶發現一個好用的呈現手法：**同一個知識領域的多頁 reading 卡，可以刻意用同一個比喻貫穿全部頁面**，讓不同知識點之間彼此呼應、更容易記憶——這不是強制規則，但可以列為內容製作的建議做法
   - 本版仍停留在規格文件階段，尚未寫入程式碼
12. **v7.4（目前版本）**：
   - **資源系統從單一資源池改為四種基礎資源**（木材／鐵礦／糧食／金幣），依建築分類決定產出種類（生產→糧食、訓練→木材、英雄→金幣、研發→鐵礦），可用於升級建築、擴地、升總部，延續「每張地圖獨立」的規則
   - **新增「研究中心」與「課程」機制**：🔬研發類底下最多一棟建築可設為研究中心，內部知識內容先分組成課程，課程底下才是課堂（＝既有的 Card）；課堂本身不直接發放資源，改為整個課程完成後一次性發放鐵礦
   - 起因：構思如何把類似《Cozy AI Kitchen》這種系列性知識內容（一個主題下有多支影片、由淺入深）納入產品架構，發現既有「建築＝領域，卡片直接掛在領域下」的結構缺少中間分組層，因此新增 Course 這個概念
   - 本版仍停留在規格文件階段，尚未寫入程式碼
13. **v7.5（目前版本）**：
   - **拿掉🎖️英雄類**：對照真實 Last War 的英雄系統（招募、升星、技能強化、裝備）後，發現這棟建築目前只是借用「英雄」名字跟造型意象，跟原版「英雄是可收集養成的獨立角色」的份量完全不對等；與其做一個名不符實的分類，決定直接移除，四大分類簡化為**三大分類**（⚙️生產／🎯訓練／🔬研發），美術資產工作量也從 20 個造型降為 15 個（3 類 × 5 階段）
   - **資源系統改為三種**（木材／鐵礦／糧食），拿掉金幣（因為金幣原本是配英雄類設計的），分類↔資源對應維持原邏輯：生產→糧食、訓練→木材、研發→鐵礦
   - **新增每日任務機制**：作為疊加在既有「答對/讀完卡片給資源」機制之上的額外獎勵管道，明確定調**資源獲取維持主動學習驅動**，不引入 Last War 那種建築隨時間自動生成資源的 AFK／放置型機制——這是刻意的產品定位選擇，呼應商業評估紀錄裡強調的「核心價值是真實知識吸收行為」
   - 起因：對照真實 Last War 遊戲機制做落差分析後，一併決定簡化英雄類、資源種類貼合精簡後的分類數量，並補上「每日任務」這個原版有、但先前規格沒設計到的常見留存機制
   - 本版仍停留在規格文件階段，尚未寫入程式碼
14. **v7.6（目前版本）**：
   - **新增「村民」視覺元素**：純裝飾性的環境動畫，在城鎮可建地上隨機走動，數量／熱鬧程度跟著總部等級或城鎮整體發展度連動，不涉及任何資料模型異動、不可操作、不影響機制數值
   - 起因：單純想讓城鎮發展有更多生氣感的視覺回饋，決定用最輕量的方式（純前端渲染邏輯）加入，避免不必要地增加資料模型複雜度
   - 本版仍停留在規格文件階段，尚未寫入程式碼
